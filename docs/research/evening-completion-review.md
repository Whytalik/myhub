# Ідея: вечірній огляд дня з % виконання ("гра")

**Статус:** 💡 ідея / не сплановано
**Дата:** 2026-07-02

## Суть

Не жити в телефоні протягом дня. Раз на день, увечері перед сном — пройтись
по всьому запланованому (routine, habits, tasks) і відмітити для кожного
пункту: зроблено / пропущено. На виході — загальний % виконання за день +
розбивка по категоріях/сферах. Пропущене відмічається явно (не просто
"тиша" = провал).

## Чому не просто новий live-чеклист

Дослідження (self-monitoring, streaks, retrospective vs real-time tracking)
підтверджує сам напрямок:

- Самомоніторинг сам по собі підвищує досягнення цілей (мета-аналіз, 19k+ учасників).
- Ретроспективна фіксація раз на день для бінарних даних ("зробив/ні") має
  прийнятний recall bias і менше нав'язлива, ніж live-трекінг.
- % стійкіший за streak: streak дає сильніший короткостроковий ефект (loss
  aversion), але одна пропущена позначка ламає все й провокує
  все-або-нічого мислення. % більш стійкий до пропусків.
- Over-tracking (постійні live-чекбокси) корелює з тривожністю/перфекціонізмом
  — вечірній формат "раз на день" знижує цей ризик.

## Що вже є в коді (не треба переробляти з нуля)

- `DayComplete.tsx` — вже показує `tasksDone/tasksTotal` і
  `habitsDone/habitsTotal` у % на екрані завершення дня.
- `habit-utils.ts` — вже рахує streak на звичку.
- `RoutineMap` (`src/lib/routine-items.ts`) — routine-пункти вже існують
  (morning/evening), але як бінарний `Record<string, boolean>` — немає
  стану "пропущено" окремо від "не позначено".
- Поточний UI (`DailyEntryForm.tsx`) розводить routine по вкладках
  Morning/Evening — це радше UI-угруповання, не жорстке блокування;
  технічно нічого не заважає відмічати пункти заднім числом.

## Чого бракує

1. Tri-state замість boolean для routine-пунктів: done / skipped / not-set.
2. Один зведений % по дню (зараз є окремо tasks% і habits%, routine% немає
   взагалі як метрика).
3. Окремий екран "вечірній огляд" — один прохід по всіх пунктах дня замість
   переходів по вкладках.
4. (Можливо) розбивка % по life spheres (`sphere.repository.ts` вже існує).

## Відкриті питання

- [ ] Чи лишати live-режим для тих, хто хоче відмічати вживу, чи повністю
      переходити на вечірній format?
- [ ] Як рахувати загальний %: рівна вага tasks/habits/routine, чи зважено?
- [ ] Як виглядає "картинка" — просто розширення `DayComplete`, чи окремий
      компонент?
- [ ] Чи потрібна історія % по днях (графік), чи досить одного дня.

## Наступний крок

Коли будемо готові рухатись — накидати план: tri-state для routine +
агрегований % + новий екран вечірнього огляду (замість/поруч з поточним
`DayComplete`).
