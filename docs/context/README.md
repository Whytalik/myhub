# Система контексту — як це працює

## Принцип

Один файл відновлює контекст після будь-якої перерви.
Система мінімальна — наповнюється в процесі роботи, не потребує окремого часу на підтримку.

## Структура

```
docs/context/
  now.md          — "де я зараз": фокус, що зроблено, що в роботі, відкриті питання
  next.md         — що робити в наступну сесію (нумерований список)
  decisions.md    — журнал архітектурних рішень (чому так, а не інакше)
  sessions/       — короткий лог після кожної сесії
    YYYY-MM-DD.md
    template.md   — шаблон для логу
```

## Цикл роботи

```
[Початок сесії]
  → Прочитай now.md (де я?)
  → Прочитай next.md (що робити?)

[Кодування]
  → Працюй

[Кінець сесії]
  → Онови now.md (що змінилось?)
  → Онови next.md (що лишилось? нові кроки?)
  → Створи sessions/YYYY-MM-DD.md (що зроблено, рішення, питання)
  → Якщо прийнято архітектурне рішення → decisions.md
```

## Підключення Obsidian

**Варіант 1 — відкрити `docs/` як Obsidian vault:**
```
Obsidian → Open folder as vault → ~/Desktop/myhub/docs
```
Wiki-links `[[now]]`, `[[decisions]]` будуть працювати між файлами.

**Варіант 2 — symlink у існуючий vault:**
```bash
ln -s ~/Desktop/myhub/docs ~/path/to/ObsidianVault/myhub
```

**Frontmatter для нотаток (опціонально):**
```yaml
---
created: 2026-06-30
tags: [project, decision, active]
status: in-progress
related: [[now]], [[decisions]]
---
```

## Що НЕ тут

- **Код** — в репозиторії, не тут
- **TODO списки** — в `next.md` (не в Obsidian окремо, щоб не дублювати)
- **Детальна документація** — в `docs/research/` або `docs/hub/`

## CLAUDE.md і ця система

`CLAUDE.md` у корені репо — перший файл що читає Claude Code.
Він містить **Session Protocol** який вказує читати `docs/context/now.md` + `next.md` автоматично на початку кожної сесії.
